Ownership and security contract

A singleton directory DO owns lobby membership atomically. Commands run through validation and serialized read/modify/persist/broadcast. Hibernatable sockets retain identity and expiry, never plaintext tokens in their attachments. Bearer session IDs are hashed in D1; invalid supplied tokens fail closed rather than minting a replacement. Socket closure retains membership. Production needs resource quotas, session cleanup and revocation before exposure. Full-directory snapshots are a bounded prototype design, not an unbounded production scaling strategy.

Snapshot and handoff requirements

Game snapshots include a schema version, command sequence, pinned asset revisions, turn order, complete deck/market partition, active auction and bid/pass flags, player inventory, powered-turn markers and deterministic random state. Client projections must exclude hidden state and must never be used as persistence snapshots. Validate membership from authenticated identity, not payload player_id. Start must be an idempotent initializing/ready handshake across directory and game objects; only advertise GAME_STARTING once initialization has committed. Persist state and bounded command deduplication records before broadcasting.

Risks & Mitigations

  • Existing Go tests miss gameplay: add independent rule fixtures, not blind parity tests.
  • Client already disagrees with Go envelopes and shapes: name compatibility boundaries explicitly.
  • Development dependency audit findings remain; runtime-only audit is clean. Do not force breaking upgrades.
  • Anonymous session creation and directory growth need quotas, rate limits and garbage collection before production.
  • Pin all asset types, including the plant deck and rule tables, not just map IDs.

Verification

Run npm run check and npm run db:migrate:local in worker. Require real D1 atomicity and immutable revision tests, DO restart and concurrency tests, authenticated game reconnect, complete multi-player game fixtures, client browser tests and a reviewed rollback strategy before cutover.

Open Questions

Choose canonical client-facing contract; decide guest recovery/account linking and lobby expiry policy; confirm target rule edition and player-count variants before finalizing game fixtures.
